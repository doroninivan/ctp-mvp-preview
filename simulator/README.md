## Попытки и порядок

Порядок вариантов создаётся при начале сцены/теста и сохраняется в попытке. Ответ хранится как индекс исходного варианта, поэтому перестановка не меняет ключ. В каждой попытке теста по два ключа на каждую отображаемую букву. Повтор использует те же задания и не является независимой проверкой.

При обнаружении другой версии исходная запись архивируется в localStorage отдельным ключом. Экран сообщает о прошлой редакции и позволяет скачать её JSON. Прогресс и ответы не переносятся, старые результаты не пересчитываются. Если архив записать нельзя, старую запись не перезаписываем, новая практика остаётся без сохранения. Удаление текущих ответов через интерфейс не удаляет архив прошлой редакции.

## Изменение контента и сборка

Единственный источник — `content.json`. `content.js` генерируется скриптом; вручную его не править. Для каждого изменения данных (включая ключи, порядок вариантов, переводы и объяснения) задайте новое уникальное значение `version`. Затем из корня проекта:

```sh
node project-admin/build-content.cjs --write
node project-admin/qa/verify-consolidated.cjs mvp/simulator
node project-admin/qa/verify-content-build.cjs
```

`content-revisions.json` хранит SHA-256 данных каждой выпущенной редакции. Сборка отвергает изменённые данные под прежним номером версии, а `--check` также отвергает устаревший `content.js`. Историю хешей не перезаписывать. Проверка встроена в `verify-consolidated.cjs`; отдельная команда только чтения: `node project-admin/build-content.cjs --check`.

Это обязательная проверка рабочего процесса, не защита от ручного обхода: статический сервер сам её не запускает, CI здесь пока нет. Браузер по-прежнему различает редакции по `version`. Перед показом новой редакции следует пройти команды выше. Текущие данные и номер версии при добавлении сборщика не менялись, поэтому текущие попытки продолжаются.
